## The seven principles — they govern everything that gets written down and kept

- **PREFERENTIAL** — the user said they want it this way.
- **LIMITING** — a boundary the user set: what is not done, and how far.
- **TIMELESS** — true today and in five months. What expires on its own stays out: no dates, no
  figures from one run, no account of the case that produced the rule.
- **BELONGS** — content lives where the session that needs it opens it. Creating a document is the
  LAST option; whatever can be merged is merged. Memories alike.
- **OBJECTIVE** — the fact with its evidence; no attributed cause, no verdict of value.
- **NON-CONDITIONING** — the state observed, never a closed door: "not observed", not "cannot".
- **CURRENT** — a line lives while it is true and serves a future session. Otherwise it is DELETED:
  git keeps it. Size is not the measure.

On conflict the higher level wins: PREFERENTIAL · LIMITING > TIMELESS > CURRENT > BELONGS >
OBJECTIVE > NON-CONDITIONING.

- **The rule travels WITHOUT its history.** The evidence, its N and the case behind it live in `docs/`.
  A `CLAUDE.md`, a memory and any document that loads on its own carry the rule, the limit and the why.
- **Admission** — only what is PREFERENTIAL, LIMITING and TIMELESS enters memory or any `CLAUDE.md`.
  Open work goes to `docs/ROADMAP.md`, documentation to `docs/`, session state nowhere.
- **Consultation** — memory and `CLAUDE.md` change only with the user's approval, with the exact change
  in view and everything in ONE consultation: what was not listed was not approved.
- **Distance** — nothing is pruned in the turn that produced it; closing evidence is what authorises it.
- **Trace** — what is being done is written to `docs/ROADMAP.md` when it STARTS and deleted when it closes.
